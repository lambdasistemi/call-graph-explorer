# Call Graph Explorer

Interactive browser for Haskell function call graphs. Upload a
`call-graph.dot` to a GitHub repo and explore it visually — click
nodes to see source code with Haddock, focus on neighborhoods,
navigate the dependency structure.

**Live:** https://lambdasistemi.github.io/call-graph-explorer/

## Quick start

1. Open the explorer
2. Enter your `owner/repo`, branch/SHA, and a GitHub token
3. Click **Add** — the graph loads automatically
4. Click any node to see its definition and Haddock in the sidebar
5. Use **Focus** to isolate a node's neighborhood, **Depth +/-** to expand

## Generating `call-graph.dot`

The explorer reads a `call-graph.dot` file from the root of your
GitHub repository. This file is generated by
[Calligraphy](https://hackage.haskell.org/package/calligraphy),
which reads GHC's `.hie` files and produces a DOT call graph.

### Requirements

- **GHC** (any version supported by Calligraphy, currently up to 9.12)
- **Calligraphy** (`cabal install calligraphy` or via Nix)
- Your project must compile with `-fwrite-ide-info`

### Step 1: Build with HIE files

You need to tell GHC to write `.hie` files during compilation.

#### With Cabal (no Nix)

```bash
cabal build all --ghc-options="-fwrite-ide-info -hiedir=.hie"
```

Or add it to your `.cabal` file permanently:

```cabal
common warnings
  ghc-options: -fwrite-ide-info -hiedir=.hie
```

Then `cabal build all`.

#### With Stack

```bash
stack build --ghc-options="-fwrite-ide-info -hiedir=.hie"
```

#### With Nix (haskell.nix)

Pass it via cabal inside the nix shell:

```bash
nix develop -c cabal build all --ghc-options="-fwrite-ide-info -hiedir=.hie"
```

### Step 2: Install Calligraphy

#### With Cabal (no Nix)

```bash
cabal install calligraphy
```

#### With Nix (haskell.nix)

Add `calligraphy` to your `shell.tools` in `flake.nix`:

```nix
shell = {
  tools = {
    cabal = indexTool;
    calligraphy = indexTool;
  };
};
```

Then `nix develop` to enter the shell.

#### With Nix (nixpkgs)

```bash
nix shell nixpkgs#haskellPackages.calligraphy
```

### Step 3: Generate the DOT file

```bash
calligraphy -i .hie --show-module-path --show-line -d call-graph.dot
```

Flags explained:

| Flag | Purpose |
|------|---------|
| `-i .hie` | Path to the `.hie` files directory |
| `--show-module-path` | Module labels become file paths (e.g. `src/Foo/Bar.hs`) — needed for source code viewing |
| `--show-line` | Adds line numbers to nodes — needed for definition extraction |
| `-d call-graph.dot` | Output DOT file |

### Optional: SVG output

```bash
calligraphy -i .hie --show-module-path --show-line -d call-graph.dot -s call-graph.svg
```

Requires `graphviz` (`dot`) in PATH for SVG rendering.

### Step 4: Commit and push

```bash
git add call-graph.dot
git commit -m "docs: add call graph"
git push
```

The explorer will fetch it from `call-graph.dot` at the repo root.

### Justfile recipe (recommended)

Add this to your project's `justfile` for easy regeneration:

```just
# Generate function call graph
call-graph:
    #!/usr/bin/env bash
    set -euo pipefail
    cabal build all -O0 --ghc-options="-fwrite-ide-info -hiedir=.hie"
    calligraphy -i .hie --show-module-path --show-line \
        -d call-graph.dot -s call-graph.svg
```

Then `just call-graph` whenever you want to update the graph.

Add `.hie/` to your `.gitignore`:

```gitignore
.hie/
```

### Filtering modules

Calligraphy supports module filtering. To graph only specific
modules:

```bash
# Only tutorial modules
calligraphy Types Balances Audit Composed \
    -i .hie --show-module-path --show-line -d call-graph.dot

# Exclude test modules
calligraphy -e 'Test.*' \
    -i .hie --show-module-path --show-line -d call-graph.dot

# Wildcard matching
calligraphy 'MyApp.Core.*' \
    -i .hie --show-module-path --show-line -d call-graph.dot
```

### Calligraphy options reference

Useful options for controlling graph detail:

| Option | Effect |
|--------|--------|
| `--exports-only` | Only exported bindings |
| `--hide-data` | Hide data types |
| `--hide-classes` | Hide type classes |
| `--collapse-data` | Collapse data types to single nodes |
| `--hide-types` | Don't show type edges |
| `-f NAME` | Forward dependency root (show what NAME depends on) |
| `-r NAME` | Reverse dependency root (show what depends on NAME) |
| `--max-depth N` | Limit dependency traversal depth |

## GitHub token

The explorer needs a GitHub token with read access to the
repository contents. A fine-grained personal access token with
**Contents: Read** permission on the target repository is
sufficient.

The token is stored in your browser's `localStorage` and never
sent anywhere except `api.github.com`.
